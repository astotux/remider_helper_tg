# Разработка Telegram-бота для создания и управления напоминаниями

## 1. Общая задача

Разработать полноценного Telegram-бота для создания, настройки и отправки напоминаний. Бот должен работать как в личных сообщениях, так и в групповых чатах.

Основная цель — сделать простой и удобный инструмент, позволяющий пользователям создавать несколько независимых напоминаний с разными расписаниями, редактировать их и отслеживать выполнение.

Проект должен быть небольшим, без излишней сложности, но с грамотной архитектурой, разделением ответственности и возможностью дальнейшего расширения.

Не использовать микросервисы и избыточные архитектурные паттерны.

## 2. Технологический стек

Использовать:

- **Node.js** — основная среда выполнения.
- **JavaScript (ES Modules)** — основной язык проекта.
- **Telegraf** — библиотека для взаимодействия с Telegram Bot API.
- **SQLite** — база данных.
- **better-sqlite3** — работа с SQLite.
- **Luxon** — работа с датами, временем и часовыми поясами.
- **dotenv** — конфигурация через переменные окружения.

Допускается использование дополнительных небольших библиотек, если они действительно необходимы.

### Важные требования к технологиям

1. Использовать актуальные стабильные версии библиотек на момент разработки.
2. Проверять совместимость выбранной версии Telegraf с актуальным Telegram Bot API.
3. Не использовать устаревшие методы и API.
4. Не привязывать бизнес-логику непосредственно к Telegraf.
5. Взаимодействие с Telegram должно проходить через отдельный слой, чтобы в будущем можно было заменить библиотеку без переписывания всей бизнес-логики.
6. Использовать SQLite с WAL-режимом, индексами и миграциями базы данных.

## 3. Основной функционал

Бот должен поддерживать два независимых сценария использования:

- Личные сообщения с ботом.
- Групповые и супергрупповые чаты.

### 3.1. Личные сообщения

Пользователь может создавать и управлять собственными напоминаниями.

Все напоминания, созданные в личке, отправляются пользователю в личные сообщения от имени бота.

### 3.2. Групповые чаты

В группах напоминания отправляются непосредственно в тот чат, в котором они были созданы.

Правила доступа:

- Создавать напоминания могут только администраторы и создатель группы.
- Редактировать напоминания могут любые текущие администраторы группы.
- Удалять напоминания могут любые текущие администраторы группы.
- Обычные участники не могут управлять напоминаниями.
- Участники могут нажимать кнопку выполнения напоминания.

Права необходимо проверять через Telegram Bot API, а не доверять данным, переданным пользователем в callback.

Если пользователь потерял права администратора, он больше не должен иметь возможности управлять групповыми напоминаниями.

При удалении бота из группы необходимо корректно обработать связанные с ней данные и расписания.

## 4. Создание напоминаний

Создание должно происходить пошагово через Inline-кнопки и сообщения бота.

Не использовать сложные команды с большим количеством параметров.

Предполагаемый сценарий:

1. Пользователь нажимает «Создать напоминание».
2. Выбирает тип расписания.
3. Настраивает дату, время или дни недели.
4. Указывает заголовок.
5. При необходимости добавляет описание.
6. При необходимости добавляет фотографию.
7. При необходимости настраивает кнопку со ссылкой.
8. При необходимости включает кнопку «Выполнено».
9. При необходимости настраивает упоминания.
10. Выбирает часовой пояс, если он ещё не настроен.
11. Получает предварительный просмотр.
12. Подтверждает создание.

На каждом этапе должны быть кнопки:

- Назад.
- Отмена.
- Продолжить (если применимо).

При отмене незавершённого создания временные данные должны очищаться.

Использовать удобный механизм пошаговых состояний (FSM или аналогичный подход).

Состояния создания и редактирования должны корректно обрабатываться, в том числе при повторных нажатиях кнопок.

## 5. Типы расписаний

Пользователь должен иметь возможность выбрать один из трёх типов.

### 5.1. Ежедневное напоминание

Поля:

- Время отправки.

Пример: каждый день в 09:00.

### 5.2. Еженедельное напоминание

Поля:

- Один или несколько дней недели.
- Время отправки.

Дни недели выбираются через Inline-кнопки.

Например:

- Понедельник.
- Среда.
- Пятница.

Можно выбрать сразу несколько дней.

Пример: каждую неделю по понедельникам, средам и пятницам в 18:30.

### 5.3. Одноразовое напоминание

Поля:

- Дата.
- Время.

Пример: 25 декабря 2026 года в 12:00.

После успешной отправки одноразовое напоминание автоматически удаляется из активных напоминаний.

Допускается сохранение истории выполнения в отдельной таблице, если это необходимо для корректной работы системы.

## 6. Часовые пояса

Это обязательная часть проекта.

VPS находится в Нидерландах, однако часовой пояс сервера не должен влиять на время отправки напоминаний.

Необходимо реализовать независимые часовые пояса.

Правила:

- В личных сообщениях часовой пояс задаётся отдельно для пользователя.
- В группе часовой пояс задаётся отдельно для конкретного чата.
- Все напоминания используют часовой пояс соответствующего контекста.
- Хранение абсолютных дат и времени выполнения должно быть нормализовано в UTC.
- Для расчётов локального времени использовать IANA time zone database через Luxon и системную базу часовых поясов.

Примеры часовых поясов:

- Europe/Amsterdam
- Europe/Moscow
- Europe/Berlin
- Asia/Almaty

При создании первого напоминания необходимо предложить пользователю настроить часовой пояс.

Также должна быть возможность изменить часовой пояс позднее.

При изменении часового пояса существующие напоминания должны пересчитываться и продолжать отправляться в соответствии с новым локальным временем.

Обязательно учитывать переходы на летнее и зимнее время (DST).

Не использовать простое прибавление фиксированного количества часов к UTC.

## 7. Содержание напоминания

Каждое напоминание должно поддерживать следующие поля:

- Заголовок — обязательный.
- Описание — необязательное.
- Фотография — необязательная, одна фотография.
- Кнопка со ссылкой — необязательная.
- Кнопка выполнения — необязательная.
- Упоминания — необязательные.

### 7.1. Заголовок

Обязательный текст напоминания.

### 7.2. Описание

Необязательное поле.

Поддерживать HTML-разметку Telegram:

- `<b>`
- `<i>`
- `<u>`
- `<s>`
- `<code>`
- `<pre>`
- `<a href="...">`

Проверять корректность HTML перед отправкой.

Не допускать отправки некорректной разметки.

### 7.3. Фотография

Пользователь может прикрепить одну фотографию.

Фотография должна отправляться вместе с напоминанием.

Необязательно загружать изображение на сторонние хостинги.

Предпочтительно сохранять Telegram file_id, чтобы повторно использовать изображение при последующих отправках.

При редактировании напоминания должна быть возможность заменить или удалить фотографию.

### 7.4. Дополнительная кнопка со ссылкой

Необязательная Inline-кнопка.

Пользователь задаёт:

- Текст кнопки.
- URL ссылки.

Пример:

`[Открыть инструкцию]`

Кнопка открывает указанную ссылку.

Проверять корректность URL и разрешённые схемы ссылок.

### 7.5. Кнопка «Выполнено»

Это отдельная необязательная функция.

Пользователь может включить её при создании напоминания.

Если функция включена, в отправленном сообщении появляется Inline-кнопка:

`✅ Выполнено`

При нажатии:

1. Бот определяет Telegram ID пользователя.
2. Сохраняет факт выполнения в SQLite.
3. Не позволяет одному пользователю засчитаться несколько раз для одного и того же напоминания.
4. Обновляет информацию о выполнивших.

В личных сообщениях достаточно учитывать факт выполнения пользователя.

В групповых чатах необходимо показывать список участников, которые нажали кнопку.

Предпочтительный формат отображения — сворачиваемая цитата Telegram HTML:

`<blockquote expandable>...</blockquote>`

Например:

Выполнили: 3

Список внутри сворачиваемой цитаты:

- @user1
- @user2
- Иван

При каждом новом нажатии список должен обновляться.

Если Telegram не позволяет корректно реализовать этот формат в конкретном типе сообщения, использовать наиболее близкую поддерживаемую альтернативу.

Важно:

- Учитывать Telegram ID, а не только username.
- Если username отсутствует, использовать имя пользователя.
- Список должен сохраняться после перезапуска бота.
- При повторном нажатии не создавать дубликаты.
- По возможности предусмотреть возможность отмены отметки выполнения.

Для периодических напоминаний каждое новое срабатывание должно иметь собственный список отметок выполнения.

Выполнение одного повторения не должно автоматически засчитываться для следующего.

## 8. Упоминания пользователей

Добавить необязательную возможность упоминания пользователей при отправке напоминания.

Важно учитывать ограничения Telegram Bot API:

Telegram не предоставляет боту стандартного метода получения полного списка участников группы.

Поэтому не пытаться автоматически получить всех участников группы.

Предусмотреть один из следующих вариантов:

- Указать конкретных пользователей вручную.
- Использовать сохранённый список пользователей, которые ранее взаимодействовали с ботом и доступны для упоминания.
- Поддержать упоминание по Telegram ID с использованием HTML-ссылок `tg://user?id=...`.

Не реализовывать фиктивный `@all`, если для него нет достоверного списка пользователей.

Функция упоминаний должна быть необязательной и не мешать обычной отправке напоминаний.

## 9. Управление напоминаниями

Основное меню бота:

- ➕ Создать напоминание.
- 📋 Мои напоминания.
- ⚙️ Настройки.
- ❓ Помощь.

При открытии списка напоминаний пользователь видит все активные напоминания в текущем контексте.

Для каждого напоминания отображать:

- Заголовок.
- Тип расписания.
- Время.
- Дни недели или дату.
- Часовой пояс.
- Наличие описания, фотографии и кнопок.

При выборе конкретного напоминания открывается меню управления:

- ✏️ Редактировать.
- 🗑 Удалить.
- ⏸ Приостановить / возобновить.
- ⬅️ Назад.

### Редактирование

Необходимо реализовать возможность изменения любого поля:

- Заголовок.
- Описание.
- Фотография.
- Кнопка со ссылкой.
- Кнопка выполнения.
- Упоминания.
- Тип расписания.
- Дни недели.
- Дата.
- Время.
- Часовой пояс (через настройки контекста).

Редактирование должно быть пошаговым, аналогично созданию.

Не требовать пересоздания напоминания при изменении одного поля.

После сохранения изменений необходимо пересчитать следующее время отправки.

### Удаление

Перед удалением показывать подтверждение.

После подтверждения напоминание удаляется и больше не отправляется.

## 10. Планировщик напоминаний

Это одна из наиболее важных частей проекта.

Не использовать исключительно setTimeout или setInterval для каждого напоминания.

Все расписания должны храниться в SQLite.

После перезапуска процесса бот должен автоматически восстановить все активные расписания.

Требования:

1. Планировщик периодически проверяет базу данных на наличие наступивших напоминаний.
2. Определяет, какие напоминания необходимо отправить.
3. Отправляет их в соответствующий чат или личные сообщения.
4. Вычисляет следующее время отправки.
5. Сохраняет обновлённое состояние в БД.

### Пропущенные напоминания

Если VPS или бот были выключены во время отправки:

- После запуска необходимо обнаружить пропущенные напоминания.
- Одноразовые напоминания, время которых прошло, необходимо отправить.
- Для периодических напоминаний необходимо обработать пропущенные срабатывания.
- Не допускать потери расписаний после перезапуска.

Предусмотреть защиту от бесконтрольной массовой отправки после длительного простоя: обработка очереди должна быть ограничена разумной скоростью, но пропущенные напоминания не должны бесследно исчезать.

### Интервал между сообщениями

Если в одном чате одновременно должны отправиться несколько напоминаний, отправлять их с интервалом в 2 секунды.

Например:

- 12:00:00 — первое напоминание.
- 12:00:02 — второе.
- 12:00:04 — третье.

Очередь должна быть устойчивой к перезапускам.

Не допускать одновременной отправки нескольких сообщений в один чат из разных частей планировщика.

Для разных чатов можно предусмотреть независимые очереди с учётом ограничений Telegram Bot API.

### Надёжность отправки

Предусмотреть:

- Обработку Telegram API ошибок.
- Повторные попытки при временных ошибках.
- Обработку Telegram rate limits (429).
- Сохранение статуса отправки.
- Защиту от повторной отправки одного и того же срабатывания после перезапуска.
- Логирование неудачных отправок.

Важно: полностью гарантировать exactly-once доставку при сетевом сбое между отправкой сообщения и записью результата в SQLite невозможно. Поэтому архитектура должна минимизировать дублирование, использовать идентификаторы срабатываний и предусматривать корректное восстановление очереди.

## 11. База данных

Использовать SQLite.

Предусмотреть отдельные таблицы для:

### users

Хранение пользователей:

- id
- telegram_id
- timezone
- created_at

### chats

Хранение групповых чатов:

- id
- telegram_id
- title
- timezone
- created_at

### reminders

Использовать внешние ключи, уникальные ограничения и индексы там, где это необходимо.

Создать систему миграций базы данных.

Не создавать всю схему базы данных вручную при каждом запуске.

## 12. Архитектура проекта

Сделать модульную структуру.

Предлагаемая структура:

```text
src/
├── bot/
│   ├── bot.js
│   ├── commands/

│   │   └── settings.handler.js
│   ├── keyboards/
│   ├── middlewares/
│   └── scenes/

├── database/
│   ├── db.js
│   ├── migrations/
│   └── repositories/
│       ├── user.repository.js
│       ├── chat.repository.js
│       ├── reminder.repository.js
│       ├── completion.repository.js
│       └── occurrence.repository.js
│
├── services/
│   ├── reminder.service.js
│   ├── scheduler.service.js
│   ├── delivery.service.js

.gitignore
```

Структура является ориентиром. Её можно немного изменить, если есть объективные причины.

### Принципы архитектуры

- Handlers отвечают за взаимодействие с Telegram.
- Services содержат бизнес-логику.
- Repositories отвечают за взаимодействие с SQLite.
- Scheduler отвечает за обнаружение наступивших напоминаний.
- Queue отвечает за последовательную отправку.
- Delivery отвечает за формирование и отправку сообщений.
- Timezone отвечает за вычисления времени и часовых поясов.
- Permission отвечает за проверку прав пользователей.

Не размещать бизнес-логику непосредственно в обработчиках Telegram.

Не создавать огромные файлы с сотнями строк, в которых находится вся логика проекта.

При этом не дробить код искусственно на десятки бессмысленных модулей.

## 13. Настройки

Предусмотреть настройки:

- Изменение часового пояса.
